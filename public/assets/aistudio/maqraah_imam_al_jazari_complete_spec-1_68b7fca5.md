# وثيقة المشروع الشاملة — تطبيق مقرأة الإمام الجزري

**الاسم العربي:** مَقْرَأَةُ الإِمَامِ الجَزَرِيِّ لِلإِقْرَاءِ وَالإِجَازَةِ بِالسَّنَد  
**الاسم الإنجليزي:** Imam Al-Jazari Center for Quran Recitation & Ijazah with Sanad  
**نوع المنتج:** تطبيق Android أصلي، مع خدمات خلفية سحابية ولوحة إدارة داخل التطبيق.  
**اللغات:** العربية، الأمهرية، الإنجليزية.  
**اتجاه الواجهة:** RTL للعربية، واتجاه مناسب للأمهرية والإنجليزية.

---

## 1. الرؤية والهدف

إنشاء منصة تعليم قرآن متكاملة للمقرأة، تربط الطلاب بالمقرئين والمعلمين والإدارة، وتدير برامج التلقين والحفظ والإجازة، والحصص والقراءات، والرصيد والدفع، والمحادثات والمجموعات والإعلانات والإشعارات. يجب أن تكون الواجهة حديثة وهادئة وسهلة الاستخدام، وأن تحافظ على هوية المقرأة العلمية القائمة على التلقي والمشافهة والإقراء والإجازة بالسند.

لا تُنشأ حسابات أو سجلات وهمية في الإنتاج. تبدأ قوائم الطلاب والمحادثات والمجموعات والطلبات فارغة، ولا يظهر إلا المحتوى الرسمي الذي تنشئه الإدارة. يسمح ببيانات توضيحية تجريبية في نسخة المعاينة فقط، ويجب ألا تنتقل إلى الإنتاج.

## 2. التقنية المقترحة والمعمارية

### تطبيق Android
- Kotlin لغة التطوير الأساسية.
- Jetpack Compose لبناء الواجهات.
- Material 3 مع مكونات تصميم مخصصة لهوية المقرأة.
- Navigation Compose للتنقل وإدارة الرجوع.
- ViewModel وطبقات Repository وUse Cases عند الحاجة، مع بنية MVVM واضحة.
- Kotlin Coroutines وFlow للعمليات غير المتزامنة وتحديث البيانات.
- DataStore لحفظ تفضيلات الجهاز مثل اللغة والثيم، وليس لتخزين بيانات حساسة أو رصيد موثوق.
- Coil لعرض الصور.
- Firebase Android BoM لإدارة إصدارات Firebase المتوافقة.
- دعم الحد الأدنى من إصدارات Android يحدد عند إعداد المشروع، مع اختبار الشاشات الصغيرة والمتوسطة.

### الخلفية وقاعدة البيانات المفضلة
**الاختيار الموصى به: Firebase** لأنه يختصر وقت بناء تطبيق Android متعدد المستخدمين، ويوفر تسجيل الدخول والإشعارات والملفات وقاعدة بيانات آنية ضمن منظومة واحدة.

- Firebase Authentication: تسجيل الدخول بحساب Google، وإدارة جلسة المستخدم.
- Cloud Firestore: قاعدة بيانات التطبيق للمستخدمين والبرامج والمجموعات والرسائل والطلبات والإعلانات والإشعارات.
- Firebase Storage: صور الملفات الشخصية والمرفقات والصور المنشورة.
- Firebase Cloud Messaging (FCM): إشعارات الجهاز.
- Cloud Functions for Firebase: العمليات الحساسة، وتعيين الأدوار، واعتماد الشحن، وخصم الدقائق، وإرسال الإشعارات، والتحقق من صلاحيات الإدارة.
- Firebase App Check: تقليل إساءة استخدام واجهات Firebase.
- Firebase Crashlytics وAnalytics اختياريان بعد إعداد سياسة الخصوصية والموافقة اللازمة.

Firestore قاعدة NoSQL وثائقية وليست SQL. يجب تصميم الوثائق والفهارس والاستعلامات وفق الشاشات الفعلية، مع تجنب تحميل كل الرسائل أو المستخدمين دفعة واحدة. تستخدم pagination وقيود الاستعلام المناسبة.

### مبدأ أمني أساسي
لا تعتبر إخفاء زر أو صفحة حماية. كل عملية حساسة يجب أن تتحقق منها Firestore Security Rules أو Cloud Functions على الخادم. لا يسمح للتطبيق بتعديل دور المستخدم أو رصيده أو سجل الحركات أو الموافقة على الدفع مباشرة. تعيين الأدوار العليا يتم من بيئة خادمية موثوقة باستخدام Firebase Admin SDK وCustom Claims، وليس من واجهة العميل. يجب اختبار القواعد بحساب طالب ومعلم ومشرف ومدير.

## 4. تجربة البداية والترحيب

تسلسل فتح التطبيق:
1. شاشة افتتاحية بشعار المقرأة واسمها العربي والإنجليزي.
2. أربع صفحات تعريفية قابلة للتمرير، مع مؤشرات تقدم وصور إسلامية مناسبة غير مزدحمة.
3. نصوص تعريفية وتحفيزية تشرح رسالة المقرأة، والتلقي والتجويد، والحفظ، والإجازة بالسند والقراءات.
4. كل صفحة تعرض النص باللغة المختارة: العربية أو الأمهرية أو الإنجليزية.
5. أزرار التالي والسابق وتخطي، مع زر أخير «ابدأ الآن / Start».
6. بعد الضغط تظهر شاشة تسجيل الدخول عبر Google.
7. في المعاينة فقط يسمح بزر دخول تجريبي واضح لا يتصل بخدمة Google ولا ينشئ حسابًا حقيقيًا.
8. في الإنتاج ينفذ Google Sign-In الحقيقي عبر Firebase Authentication، ثم ينشأ/يحدّث ملف المستخدم في Firestore وفق UID الموثق.
9. تظهر رسالة ترحيب قصيرة ثم تختفي تلقائيًا، وبعدها تفتح الصفحة الرئيسية.
10. لا تطلب صلاحيات أو بيانات غير لازمة، ولا تجمع رقم الهاتف إلا عند الحاجة وبموافقة المستخدم.

## 5. شريط التنقل الرئيسي

خمسة أزرار ثابتة بالترتيب:

`[حسابي] [باقاتي] [الرئيسية] [المحادثات] [الإدارة]`

- الرئيسية في الوسط، أكبر بصريًا من بقية الأزرار.
- البرامج التعليمية تكون داخل الصفحة الرئيسية ولا تضاف كزر سادس.
- زر الإدارة يظهر وفق الصلاحية. إذا حاول الطالب الوصول إلى صفحة إدارية عبر رابط أو مسار مباشر تظهر رسالة «ليس لديك صلاحية الوصول إلى هذه الصفحة» ولا تُحمّل بيانات الإدارة.
- كل صفحة داخلية تحتوي زر رجوع واضحًا في أعلى الصفحة. يجب أن يحترم الرجوع سجل التنقل، وإذا لم توجد صفحة سابقة يرجع إلى الرئيسية. لا تضع أزرار رجوع متعارضة مع زر الرجوع الخاص بالنظام.

## 6. الصفحة الرئيسية

- ترحيب باسم المستخدم.
- شريط علوي يعرض صورة/أفاتار المستخدم واسمه، كود الطالب، ورصيد الدقائق بوضوح.
- بطاقات البرامج الأربعة:
  1. التلقين وتصحيح الأداء.
  2. الحفظ المكثف.
  3. الإجازة برواية حفص.
  4. الإجازة بالقراءات السبع.
- كل بطاقة تفتح صفحة تفصيلية فيها الوصف والشروط والمميزات وآلية الدراسة وحالة التسجيل وزر التسجيل.
- أقسام مختصرة للإعلانات والمنشورات وآخر الإشعارات.
- محتوى الصفحة يتغير حسب اللغة، مع عدم إظهار بيانات تجريبية في الإنتاج.

## 7. البرامج والتسجيل

- المدير يستطيع فتح التسجيل أو إغلاقه لكل برنامج.
- صفحة البرنامج تعرض الاسم والوصف والشروط والمميزات والمتطلبات وخطوات الدراسة.
- نموذج التسجيل يجمع فقط البيانات الضرورية، مثل الاسم والعمر والجنس والمدينة ووسيلة التواصل والمستوى القرآني والخبرة السابقة والبرنامج المطلوب والفترة المناسبة.
- يمنع التسجيل المتزامن في برامج متعارضة وفق سياسة الإدارة. إذا كان الطالب مسجلًا في برنامج آخر تظهر رسالة تشرح ذلك وتوجهه للتواصل مع الإدارة أو إلغاء البرنامج السابق وفق الصلاحية والسياسة.
- ينشأ طلب تسجيل بحالة pending، ثم يوافق المشرف المخوّل أو يرفض مع كتابة سبب واضح.
- يتلقى الطالب إشعارًا عند قبول الطلب أو رفضه.
- يجب حفظ سجل حالة الطلب وتاريخه والموظف الذي عالجه.

## 8. المحادثات الخاصة

- قائمة سردية رأسية شبيهة بتطبيقات المراسلة الحديثة: صورة/أفاتار، الاسم، آخر رسالة، وقتها، وعدد غير المقروء.
- تبدأ القائمة فارغة في الإنتاج باستثناء الحساب الرسمي الثابت للمقرأة/الإدارة إذا قررت الإدارة تفعيله.
- زر (+) لبدء محادثة، يعرض الحسابات المسموح بها فقط.
- فصل ظهور الحسابات بحسب الجنس: لا يرى المستخدم العادي حسابات الجنس الآخر. الاستثناءات الإدارية للمدير والمعلم المصرح لهما تكون وفق سياسة مكتوبة وقواعد خادمية.
- شاشة المحادثة تعرض صورة واسم الطرف الآخر وحالته وآخر ظهور، ثم الرسائل بترتيب زمني.
- الضغط على رأس المحادثة أو الصورة يفتح الملف الشخصي: الاسم والصورة والنبذة وكود الطالب والبرامج المسجل بها، بحسب الصلاحيات.
- الرسائل النصية والإيموجي وإرفاق الصور فقط؛ لا تضف تسجيلًا صوتيًا.
- دعم حالة الإرسال والقراءة، ومنع قراءة محادثات غير مصرح بها.
- مركز الإشعارات مرتبط بعدد الرسائل غير المقروءة، وتتحدث الشارة عند القراءة.

## 9. المجموعات

- تبويب مستقل للمجموعات بجانب المحادثات الخاصة.
- يرى الطالب مجموعاته فقط.
- أمثلة تنظيمية: رجال صباحي/مسائي/ليلي، نساء صباحي/مسائي/ليلي، وملتقى عام للرجال وآخر للنساء.
- قائمة المجموعة تعرض الصورة والاسم وآخر رسالة والوقت.
- صفحة المجموعة تعرض الاسم والصورة وعدد الأعضاء والمتصلين وغير المتصلين، والرسائل.
- دعم النص والإيموجي والصور.
- زر (+) لإضافة طالب يظهر للمشرف/المدير المخوّل فقط.
- المدير يستطيع إنشاء المجموعات وتعديلها وإضافة الطلاب وإزالتهم وفق سجل تدقيق.
- تحقق الخادم من عضوية المستخدم قبل قراءة أو إرسال الرسائل.

## 10. المنشورات والإعلانات

### المنشورات
- يمكن للمستخدمين نشر مقالات وفوائد ومواد نصية مناسبة للمقرأة.
- يظهر اسم الناشر ووقته.
- إعجاب وتعليقات وإعادة نشر/مشاركة داخل التطبيق.
- صلاحيات تعديل/حذف المنشور لصاحبه والإدارة وفق السياسة.
- أدوات إبلاغ وإشراف على المحتوى عند الحاجة.

### إعلانات المقرأة
- المدير أو الموظف المخوّل ينشر عنوانًا بارزًا ونص الإعلان وتاريخه.
- الأحدث يظهر أولًا.
- يمكن تثبيت إعلان مهم، وتحديد فترة ظهوره، وإرسال إشعار للمستهدفين.

## 11. الإشعارات

مركز إشعارات مرتب من الأحدث إلى الأقدم، يشمل:
- طلب التسجيل وقبوله أو رفضه مع السبب.
- طلب شحن الرصيد وقبوله أو رفضه.
- إضافة الرصيد مع الرصيد السابق والحالي والتاريخ.
- قرب نفاد الرصيد، والرصيد المتبقي، والخصم، والتكريم، والسلفة إن كانت سياسة السلفة مفعلة.
- مواعيد الاختبارات.
- الرسائل الجديدة.
- طلبات واردة للموظفين المخولين، مع أزرار الموافقة والرفض وسبب الرفض.
- تسجيل وقت الإشعار ووقت قراءته وربطه بالمستخدم.
- إرسال Push عبر FCM، مع إبقاء مركز الإشعارات داخل التطبيق هو سجل الإشعارات.

1. يختار الطالب الباقة.
2. يختار وسيلة الدفع.
3. تظهر بيانات التحويل والمبلغ وزر نسخ رقم الحساب.
4. يدخل اسم المرسل ورقم الهاتف ورقم العملية ويرسل الطلب.
5. تظهر رسالة «تم استلام طلبك، انتظر موافقة المحاسب».
6. يراجع المحاسب الطلب ويتحقق من التحويل خارج التطبيق، ثم يوافق أو يرفض مع السبب.
7. عند الموافقة تنفذ Cloud Function معاملة ذرية تضيف الدقائق وتسجل حركة الرصيد وترسل إشعارًا.
8. لا يسمح بتكرار اعتماد نفس رقم العملية دون مراجعة.

### صفحة رصيدي
- الرصيد الحالي بالدقائق بارز.
- سجل زمني لكل شحن وخصم وتكريم وسلفة/تسوية إن كانت مفعلة.
- الرصيد قبل العملية وبعدها والمقدار والتاريخ والسبب والموظف الذي نفذ العملية.
- السجل غير قابل للتعديل من الطالب، ولا تحذف الحركات المالية؛ التصحيح يكون بحركة عكسية موثقة.

## 13. احتساب دقائق القراءة

- يحتسب الاستخدام بحسب دقائق القراءة الفعلية لا عدد الصفحات.
- المعدل المعتمد في إعدادات النظام: 5 بير لكل دقيقة كمرجع تسعيري عند حساب قيمة الخدمة، مع إمكانية تعديل السياسة إداريًا.
- يجب أن يكون تسجيل الدقائق من المعلم/الموظف المخوّل أو خدمة موثوقة، مع حفظ وقت الجلسة والطالب والمعلم وعدد الدقائق والملاحظات.
- الغياب لا يخصم منه شيء.
- يجب منع الرصيد السالب إلا إذا كانت سياسة السلفة مفعلة ومصرحًا بها.
- أي تعديل يدوي للرصيد يسجل في audit log مع السبب والمنفذ.

- الخصوصية والأمان.
- تسجيل الخروج.
- المساعدة والدعم.

## 15. الأدوار والصلاحيات

### الطالب
- إدارة ملفه المسموح به.
- التسجيل في البرامج.
- استخدام المحادثات والمجموعات التي ينتمي إليها.
- المنشورات بحسب سياسة النشر.
- مشاهدة رصيده وسجل حركاته.
- تقديم طلبات الشحن.
- لا يصل إلى الإدارة ولا يضيف أعضاء أو يعدل برامج أو باقات أو مجموعات.

### المعلم
- إدارة حصصه وطلاب المجموعات المصرح بها.
- تسجيل دقائق القراءة والتقدم والملاحظات وفق الصلاحية.
- متابعة الطلاب المكلف بهم.
- لا يمنح نفسه صلاحيات إدارية ولا يغير إعدادات الدفع أو أدوار الموظفين.

### المشرف
- مراجعة الطلبات التي فوضه المدير بها.
- إدارة المجموعات والبرامج والباقات ضمن حدود التفويض.
- إضافة طالب إلى مجموعة إذا كان مخولًا.
- أزرار (+) للإضافة وأيقونات القلم للتعديل تظهر له حيث يسمح التفويض.
- لا يستطيع رفع صلاحيات نفسه أو إنشاء مدير أعلى.

### المدير العام
- صلاحيات كاملة: المستخدمون والموظفون والبرامج والباقات والمجموعات والإعلانات والطلبات والإعدادات والأدوار وسجلات التدقيق.
- إضافة مشرف عادي ومعلم إضافي.
- تجميد أو تفعيل المستخدم وتعديل بياناته وإدارة عضوياته.

## ملاحظة تشغيلية

هذه الوثيقة مواصفات تنفيذ شاملة وليست تطبيقًا جاهزًا أو اتصالًا فعليًا بقاعدة بيانات. يجب إدخال إعدادات Firebase الخاصة بالمشروع، وإعداد OAuth وSHA fingerprints، ونشر Cloud Functions والقواعد، واختبار الصلاحيات قبل استخدام بيانات الطلاب الحقيقية.
